This covers the **native host build** (`/usr/sbin/asterisk`, confirmed via `asterisk -V` → `Asterisk 22.10.1`). The container build in [Docker stack](/setup/docker-stack) uses the identical `./configure` invocation, run fresh inside the image after `make distclean`.

## Dependencies installed

The host build's `config.log` and `menuselect.makeopts` show a build against these libraries (dev packages), which is also the exact package list the Dockerfile's builder stage installs on `ubuntu:24.04`:

<CodeGroup>

```bash apt (Debian/Ubuntu)
apt-get install -y \
  build-essential pkg-config \
  libedit-dev uuid-dev libxml2-dev libsqlite3-dev \
  libjansson-dev libssl-dev libsrtp2-dev libncurses-dev \
  wget curl ca-certificates file git
```

</CodeGroup>

<Note>
  `libjansson-dev` and pjproject headers are installed, but the actual jansson and pjproject code Asterisk links against is **bundled and built from tarballs Asterisk downloads itself** (see `--with-*-bundled` below) — the dev packages just satisfy `./configure`'s initial header probes.
</Note>

## Configure flags

```bash
./configure --with-pjproject-bundled --with-jansson-bundled
```

Confirmed verbatim in `config.log`:

```text
It was created by asterisk configure 22, which was
generated by GNU Autoconf 2.72.  Invocation command line was

  $ ./configure --with-pjproject-bundled --with-jansson-bundled
```

- **`--with-pjproject-bundled`** — downloads and builds Asterisk's own pinned pjproject (2.17 as of this tree) instead of linking a system libpjproject. Avoids version skew between Asterisk and pjproject and sidesteps needing pjproject dev packages at all.
- **`--with-jansson-bundled`** — same idea for jansson (JSON library used heavily by ARI/PJSIP). Both end up **statically linked into Asterisk's own libraries** — confirmed by `ldd`ing the built binary and modules in the Dockerfile (no `libjansson*.so` or `libpj*.so` shows up as a dynamic dependency).

## menuselect: what got skipped, and why

`make` uses whatever `menuselect.makeopts` was already staged in the tree; nothing was hand-picked interactively. Reading the actual `menuselect.makeopts` and cross-referencing `config.log`'s dependency probes shows the build is **not** missing anything by mistake — every skipped module failed a real dependency check because this is a minimal build host with no database client libraries, no message-queue clients, and no proprietary/telephony hardware libs installed.

| Missing library on this host | Modules disabled as a result |
| --- | --- |
| `libpq` (PostgreSQL client) | `cdr_pgsql`, `cel_pgsql`, `res_config_pgsql` |
| `unixODBC` | `cdr_adaptive_odbc`, `cdr_odbc`, `cel_odbc`, `res_odbc`, `res_odbc_transaction`, `res_config_odbc`, `func_odbc` |
| `libcurl` / `curl-config` | `func_curl`, `res_curl`, `res_config_curl`, `res_http_post`, `res_http_media_cache` |
| FreeTDS (`libtds`) | `cdr_tds`, `cel_tds` |
| `libradiusclient-ng` | `cdr_radius`, `cel_radius` |
| beanstalkd client | `cdr_beanstalkd`, `cel_beanstalkd` |
| DAHDI kernel headers | `chan_dahdi`, `codec_dahdi`, `res_timing_dahdi` |
| `libjack` | `app_jack` (confirmed in `config.log`: `cannot find -ljack: No such file or directory`) |
| `unbound` | `res_resolver_unbound` |
| `spandsp` | `res_fax_spandsp` |
| `net-snmp` | `res_snmp` |
| Lua | `pbx_lua` |
| iksemel/XMPP libs | `res_xmpp` |
| libical / calendar libs | `res_calendar_caldav`, `res_calendar_ews`, `res_calendar_exchange`, `res_calendar_icalendar` |
| OpenLDAP | `res_config_ldap` |
| corosync | `res_corosync` |
| STIR/SHAKEN deps | `res_stir_shaken`, `res_pjsip_stir_shaken` |
| geolocation libs | `res_geolocation`, `res_pjsip_geolocation` |
| Sangoma/Digium proprietary libs | `res_digium_phone`, `res_pjsip_config_sangoma` |
| kqueue (BSD-only) | `res_timing_kqueue` |

None of this matters for the container/portal workflow this stack is built around: PJSIP, ARI, `chan_websocket`, `res_prometheus`, CDR-to-flat-file, and the codecs actually used (`ulaw`/`alaw`) all built and are all that `docker/etc-asterisk/*.conf` relies on.

<Warning>
  If you later need any module in the table above (e.g. `cdr_pgsql` for a Postgres-backed CDR store), install the corresponding dev package, re-run `./configure`, and rebuild — `menuselect.makeopts` only reflects what was detected at the time it was generated; it does not need manual editing to pick up a newly-satisfied dependency, but the module needs to not be explicitly excluded from its category.
</Warning>

## make / make install

```bash
make -j"$(nproc)"
make install
```

`make install` populates `/etc/asterisk` with the full interactive sample config set and creates the runtime directory skeleton (`/var/lib/asterisk`, `/var/log/asterisk`, `/var/spool/asterisk`, `/var/run/asterisk`, etc.) using the compiled-in defaults. The Docker image replaces the sample configs with a purpose-built minimal set — see [Asterisk configuration reference](/reference/asterisk-config).

## Verifying the build

```bash
# Version and confirm binary location
/usr/sbin/asterisk -V
# => Asterisk 22.10.1

# Confirm PJSIP, ARI, and prometheus modules actually loaded
asterisk -rx "module show like res_pjsip.so"
asterisk -rx "module show like res_ari"
asterisk -rx "module show like res_prometheus"

# Confirm the HTTP server (backs ARI, transport-ws, and /metrics) is up
asterisk -rx "http show status"
```

See [Runbook](/operations/runbook) for the full set of health-check commands used day to day.
